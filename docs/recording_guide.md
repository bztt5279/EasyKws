# EasyKws 数据集录制与标注指南

[文档首页](README.md) · 下一步：[从录音到部署的操作教程](tutorial.md)

你可以自己组织这次录制：先选一个喜欢的唤醒词，再邀请几位朋友按任务单录制，随后跟着教程训练和验证。本指南分别说明组织者需要准备什么、参与者需要说什么，以及录完怎样检查和整理。

示例唤醒词为 **「你好小A」**，A 统一读 /ēi/；更换目标词时，先统一词句和读音，再安排录制。

个人或小团队的训练采集任务集中在两类：**目标词正样本和相似对照负样本**。普通语音、音乐、环境噪声及 RIR 使用合适的公开资源补充；参与者无需把这些素材重新录一遍。

如果只想确认软件能运行，直接执行[合成演示](tutorial.md#1-先跑一遍合成演示)。下面采集的是真人语音，用于后续训练和评估。仓库没有数据集录音程序；可使用能保存原始 WAV 的外部录音软件。`easykws-listen` 是模型推理入口，不负责制作训练集。

## 1. 录制前先决定三件事

**先决定什么算目标词。** 例如「你好小A」是正样本，而「小A」「您好小A」是否也应唤醒，必须事先确定。支持的变体作为正例；明确不支持的作为对照负例；尚未决定的先标记待审。不要看到模型误触发后，悄悄改变标签。

**再安排朋友们怎样分组。** 一部分人的录音用于训练，另留人员用于验证和最终测试。例如，5 位独立说话人可按 3/1/1 分组；这只是方便起步的安排，不是效果保证。每位参与者都录目标词和相似对照词，验证人员还可以另录新的连续会话，用于校准。

当前 train/val/test 管线按实际说话人及同源关系隔离，至少需要 3 个独立单元。同一人的不同编号、日期或设备录音仍属于同一个人。若只希望训练个人专用模型，跨场次评估需要另行设计，不能将一个人的不同场次填成不同说话人。

**最后决定怎样评估。** 训练、验证、最终测试在实验前分配；连续校准录音另行采集，可来自验证人员的新场次，不能来自训练或最终测试人员。测试人员的录音和音色参考也不用于 VC、噪声混合或其他训练扩充。参与者同意录制后再采集，使用匿名编号保存身份映射。

## 2. 设备与文件设置

优先使用接近目标使用场景的麦克风。只有手机或电脑麦克风时也可先试录，但要记录设备差异，不能据此承诺目标硬件上的效果。

| 项目 | 操作要求 |
| --- | --- |
| 保存格式 | 未压缩整数 PCM WAV；起步可选 16 kHz、单声道、16 bit |
| 原生格式不同 | 保留原件；由整理人员显式选择通道与重采样。不要只改文件扩展名 |
| 设备设置 | 记录采样率、声道、输入增益，以及设备能否关闭自动增益、降噪、回声处理 |
| 后期处理 | 不对原件统一放大、归一化、降噪、压缩或加音效 |
| 多通道设备 | 保留原始多通道文件，记录选用通道；程序的通道平均并不等同于波束形成 |
| 文件传递 | 按文件传输，避免聊天软件转成语音消息重新编码 |

软件输入端最终采用 16 kHz 单声道；录音设备能否直接提供该格式与当前 `easykws-listen` 是否支持，是两件不同的事。实时入口暂不提供原生采样率转换。

## 3. 每个人先做一次试录

1. 将设备放稳，嘴部到麦克风可先取约 0.5～1 米，正面自然说话。
2. 开始后留约 2 秒安静段，连续说几次完整目标词，每次之间留约 2 秒。
3. 补录自然的快、慢、轻声和稍大声，各说一次，再说一次「你好小A，播放音乐」。
4. 结尾再留约 2 秒，保存原始文件，试听开头、结尾和较轻的发音。
5. 检查是否录到了错误设备、是否破音、是否截掉首尾字音。发现问题先调整，再正式录制。

这些距离和停顿是便于组织录音的起步设置，不是模型最佳参数。不要刻意模仿示范者的音色、口音和语调；示范只统一目标词读法。

## 4. 正样本怎样录

可以按组连续录成一个文件，不用每说一句就保存一次。不要把组名、序号和次数念出来。读错或被打断时，停顿后重说，并记录大致位置；不要覆盖原件。

下面是**首轮试采任务单**，便于发现采集问题，不是训练出好模型所需的充分数据量。每组先录 5 次，检查可用后再根据说话人、场景覆盖和验证错误决定补录规模。

| 组别 | 怎样说或怎样放置 | 示例文件名 |
| --- | --- | --- |
| 自然语气 | 像平时叫人，保持完整连贯 | `speaker_001_normal_take1.wav` |
| 稍快、稍慢 | 各录一组，不吞字，不逐字拖长 | `speaker_001_fast_take1.wav` |
| 轻声、稍大声 | 正常发声，不用极端耳语或尖叫替代音量变化 | `speaker_001_soft_take1.wav` |
| 距离变化 | 设备不动，人换位置；记录实际距离 | `speaker_001_far_take1.wav` |
| 方向变化 | 用实际可能出现的侧向角度，记录朝向 | `speaker_001_side_take1.wav` |
| 目标词接指令 | 自然停顿或顺接指令，不截掉后续语音 | `speaker_001_command_take1.wav` |

房间放不下计划距离时，填写实际值。轻声、距离、设备增益是不同因素，不要通过提高输入增益把远距离录音重新变成近距离幅值。先得到稳定的安静录音，再根据需要补充不同距离和方向。真实使用环境中的效果需通过独立的连续录音另行验证。

## 5. 负样本怎样录

参与者的负样本任务聚焦于容易与目标词混淆的词句。先确定哪些变体不应唤醒，再请每个人自然地说几次：

| 类型 | 示例与注意事项 |
| --- | --- |
| 近似或近音词 | 如「你好小B」「你好小安」；先确认不属于接受范围 |
| 不完整词 | 如「你好」「小A」；仅在明确不支持这些变体时标为负例 |

普通讲话、音乐、环境噪声和房间脉冲响应（RIR）从合适的公开数据集准备，不要求参与录音的人另录这些素材：

| 资源 | 可选来源 | 接入方式 |
| --- | --- | --- |
| 普通语音及非目标词语 | [Mobvoi（OpenSLR 87）](https://www.openslr.org/87/) | 提供本机元数据适配器，先确认类别映射 |
| 语音、音乐和噪声 | [MUSAN（OpenSLR 17）](https://www.openslr.org/17/) | 自行下载、整理，按用途写入样本或资源清单 |
| 脉冲响应与噪声 | [RIRS_NOISES（OpenSLR 28）](https://www.openslr.org/28/) | 自行整理为噪声/RIR 资源，供增强配置引用 |

使用前核对各数据集的许可、来源和适用条件。公开语音中的关键词是否为负类，也需针对自己的目标词判断。程序不自动下载这些数据；具体接口见[扩充导入](reference/data_expansion.md)和[增强参考](reference/augmentation.md)。

公开素材可用于训练和增强，但不能代替真实场景下的连续校准与效果验证。听到完整目标词的片段不能直接标为负例；混入目标词时应重审、切分或标出正例窗口。全零文件不作为训练样本；连续校准里的真实静音或有限零值音频则可以推进观测时钟。

## 6. 文件组织、切分与质量审核

原始录音与整理后的切片分开保存，全部放在仓库之外。例如：

```text
my-kws-data/
├── raw/speaker_001/                  # 原件，只读保留
├── audio/speaker_001/                # 供程序读取的单条样本
├── records/                         # 录制条件和切分记录
├── recordings.jsonl                 # 样本清单
└── calibration/                     # 另行采集的连续会话
```

一份录制记录至少写明：匿名说话人编号、场次编号、设备、格式、设备处理设置、房间、日期、距离、方向、组别、口误及重录位置。不能只依赖文件名保存全部信息。

整理人员手工或用外部工具切分连续录音，每条训练样本保留完整词句与适量首尾背景，不要卡着可听字音切边。当前仓库没有自动切句和人工听审界面；切片、时间位置和审核记录由使用者准备。

| 检查项 | 处理方式 |
| --- | --- |
| 首尾截断、错词、其他人同时讲话 | 复听，重录或记录排除理由 |
| 波形削顶、明显破音 | 先核对设备增益；已有失真不能靠缩小幅度修复 |
| 长静音、点击、敲桌子等干扰 | 按用途判断，不批量假定全部可用 |
| 格式错误、空文件、重复内容 | 修正文件或显式去重，保留来源 |
| 词句边界有歧义 | 标记 `pending`，由负责人决定标签 |

同一原始文件的所有切片共享 `source_recording_id`；`sample_id` 每条唯一。一个人的试录、补录、重录都使用相同 `speaker_id`。VC 和增强变体还需记录父样本与参考资源。归属关系不能因为改名、换封装或重切而丢失。

清单格式见[录音清单参考](reference/recording_manifest.md)。v1 中真实录音填 `origin="recorded"`，目标词标签为 `0`，非目标为 `-1`；程序不根据文字自动纠正标签。v2 的来源与用途分别声明，不能把外部生成的语音误标成测试音调，也不能把测试音调标成真人录音。

## 7. 连续校准与最终测试要另行准备

训练切片回答「这一条是否包含目标词」，连续录音回答「一直听下去会产生哪些事件」。两者不能互相替代。

这是一项独立于参与者训练采集的任务：在实际使用条件下另行录制连续会话，并保留讲话、停顿和背景的真实顺序。按采样时钟标记每次目标词对应的正例窗口，以及确认不含目标词的负区间；未审核的区间不自动当负例。窗口定义在比较候选前固定，不为某个模型的输出临时放宽。设备断流处拆分新会话，不把丢失的时间补成静音。

当前校准会话只接受 16 kHz 单声道整数 PCM WAV。记录文件 SHA256、实际样本数、说话人和事件窗口，格式见[校准参考](reference/calibration.md)。校准人员不得与训练、最终测试人员冲突；背景素材也不能复用实际训练增强资源。人工拼接会话用于接口检查时必须声明测试用途。

最终测试数据在选择模型和阈值后再使用。当前 `calibrate` 明确拒绝 `test` 集作为选择输入；仓库尚未提供独立的最终连续测试报告命令。不要把最终测试改名成校准集来绕过限制。真实测试方案需单独记录命中、漏检、误触发、持续时间与设备条件。

## 8. 交给训练人员前检查

- [ ] 原始文件保留，整理文件能播放，录音条件有记录。
- [ ] 目标词读法及接受范围一致，正负标签经过复核。
- [ ] 说话人、场次、原始文件、切片之间的关系完整。
- [ ] 试录、补录、参考音色和派生样本遵守既定划分。
- [ ] 测试数据留出；连续校准录音及标注另外准备。
- [ ] 异常和排除项有理由；实际数量与任务单不一致时已说明。

完成后按[操作教程](tutorial.md#2-准备自己的录音与清单)生成清单并运行 `plan`。程序检查通过只能说明格式与已声明关系符合规则，不能替代试听、正确标注和真实效果测试。
