# 来源、开源项目与许可证

[文档首页](README.md) · [技术报告](technical_report.md) · [第三方依赖明细](../NOTICES.md)

本页说明实际采用的方案依赖哪些上游项目、继承了什么，以及当前仓库实际包含什么。代码来源、运行依赖、数据集、引擎权重和生成音频分别记录；其中一个对象的许可证不能代替其余对象的许可核对。

## 1. 当前仓库提供什么

本项目自编代码以 [Apache-2.0](../LICENSE) 发布。模型及部分训练实现保留其 WeKWS 派生来源说明；可核实的来源与修改记在[模型来源记录](reference/MODEL_PROVENANCE.md)。本项目不声称所有算法原创。

仓库提供源码、文档、示例配置和测试音调生成器。没有真人录音、历史业务数据、生成语音、特征缓存、预训练唤醒模型或外部生成引擎。合成演示里的「VC/公开负样本」是接口夹具，不是实际运行了生成模型或下载了公开语料。

## 2. 上游项目与实际关系

| 项目 | 在本项目中的作用 | 当前分发与版本事实 |
| --- | --- | --- |
| [WeKWS](https://github.com/wenet-e2e/wekws) | 模型及部分训练实现的历史来源，采用留存的 DS-TCN 与最大池化损失实现 | 包含经适配的派生实现；历史提取 commit/tag 未记录，不能用最新版本替代历史来源 |
| [Seed-VC](https://github.com/Plachtaa/seed-vc) | 历史实践中的说话人转换式数据扩充 | 主仓标示 GPL-3.0；本仓库没有其代码、权重或运行入口，只接受外部生成并审核的产物 |

上述「历史使用」来自留存记录，并不表示本轮重新运行或复现了那些工具。具体生成版本、权重和输出条件应以相应生成记录为准，不能从当前项目主页反推旧实验。

### Apache-2.0 与 GPL-3.0 的说明

不能笼统地说两者完全不兼容。[Apache 官方说明](https://www.apache.org/licenses/GPL-compatibility.html)指出，Apache-2.0 代码可以进入 GPLv3 作品；将 GPLv3 实现纳入仍仅以 Apache-2.0 分发的派生作品则涉及不同的分发要求。

本仓库选择保持生成引擎在外部运行，并不因此推断「曾使用 GPL 工具生成过音频就不可使用」。工具源码、模型权重、参考音色与输出音频要分别核对；本页也不替某个引擎的全部权重或输出作统一许可承诺。

## 4. 用户录音与生成产物怎样进入管线

- **真人录音**：按[录制指南](recording_guide.md)采集，填写说话人、场次、原始录音、审核状态和标签。是否允许使用及公开由实际权利和同意范围决定，程序不会认证这些声明。
- **外部 VC 产物**：先记录源录音、参考音色、引擎、权重、配置与生成状态，再做声学检查和听审。使用 v2 的 VC 来源类型，不要伪装成真人录音。
- **噪声和 RIR**：单独记录来源、哈希及划分，不作为普通说话人条数统计。训练资源不得来自已知评估内容。
- **测试夹具**：程序生成的音调标为测试用途，沿准备、训练、校准和导出传播。它们证明接口，不证明语音生成质量或识别能力。

哈希只能识别内容是否与记录一致，不证明来源可信、许可有效或标注正确。用途标记用于阻止工具链静默丢失属性，不是防伪认证。

## 5. 贡献归属与引用

模型及部分训练实现应明确致谢 WeKWS。数据集和外部生成工具按实际使用的版本、官方说明和引用要求记录；代码、引擎权重与生成数据不要混用一份许可证声明。当前依赖包的项目主许可证、关键底层库及依据链接集中在 [NOTICES](../NOTICES.md)，避免在多个文档复制不一致的矩阵。

项目侧的主要工作是：将录音与派生关系通用化，保留增强与训练的数值语义，整理实际曝光和恢复流程，让连续校准与运行时共用触发实现，并建立模型、前端、CMVN 和阈值之间的可核对关系。它们是工程实现与方法整理，不改写上游归属，也不把架构本身表述为原创。

详细源码快照与变更说明见[模型来源记录](reference/MODEL_PROVENANCE.md)。历史结果为何不直接搬入当前项目，见[历史结果边界](reference/HISTORICAL_RESULTS.md)。
